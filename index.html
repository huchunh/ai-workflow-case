Building the complaint-ratio skill with AI

Every day I clean the same complaint-ratio Excel, flag the risky ratios, and send one picture per port to the team. This page shows how I turned that routine into a reusable AI skill, one conversation and one correction at a time.

In1 Excel

Sheet named by data date. Port block A–H, City block I–O.

→
Skill9 rules

Clean, flag at 0.15%, merge, freeze panes.

→
Out12 images + 1 xlsx

Two images per port, saved to a dated folder on my Desktop.

A
The problem

A ten-step chore that had to be perfect every morning

The source file comes with group-header rows, "Total" rows, cities with nothing but zeros, and formatting left over from upstream. Before anyone can read it, I had to delete rows, clear red and bold, re-flag every ratio against the 0.15% threshold, merge the port cells, then screenshot each port twice. It was slow, and one missed cell meant a wrong alert to a port team.

The rules lived only in my head. The first job was getting them out.

B
How I built it with AI

Describe, run, check, correct, save

  1. Explain the process in my own words

    I uploaded a real day's file and walked Claude through what I do by hand, in the order I do it. No code, just the steps a new teammate would need.

    delete row 2, copy column A into B, remove red and bold in K–O, delete every "Total" row…

  2. Let it run on the real file

    Claude worked on a copy (never the original), used openpyxl so the Excel styles survived, and gave back a cleaned xlsx plus a count of what it deleted and flagged.

  3. Check the output against what I would have done

    This is where the real rules came out. Reading the result, I found cases I had never put into words, like a value that shows as 0.15% in Excel but is really 0.1493%.

    0.1493 shows 0.15, flag it. But in column O, only flag above 0.15%.

  4. Correct it, precisely

    Each correction became an exact rule: round half-up to two decimals for K–N, strict "greater than" for O, leave I and J exactly as the source formatted them, delete trailing rows that only hold a port name.

  5. Make the images look like Excel

    Instead of screenshotting Excel by hand, Claude renders each port as an HTML table (Arial and Noto Sans CJK, 1px borders, pink and yellow headers) and captures it with Playwright at 2× resolution, then looks at one image to verify before delivering.

  6. Save it as a skill

    Once a run came out right, I asked Claude to remember the whole process. It became the complaint-report skill: now one request does the cleanup, all 12 images, and saves them to a dated folder on my Desktop (report/YYYY.MM.DD).

  7. Version it like code

    I collect changes and update the skill once, and every update first backs up the old SKILL.md to a skill backups folder, so I can always roll back.

  8. Reuse the pattern

    The same recipe now covers the Courier tab of the DSP customer-ratio file: one image per port with the "Delivered but Not received" NO / YES / Total sub-columns under a merged header.

C
The rules, made precise

What the skill actually does, in order

Order matters. All row deletions happen before merging, otherwise merged ranges break.

#StepColumns
1Delete the group-header row (e.g. "FLA"); copy column A, value and style, into BA–B
2Leave City and Total Ratio untouched, keeping the source's own red/boldI–J
3Clear red and bold from every ratio cellK–O
4Delete every row where City is "Total"I
5Delete cities where every ratio is 0 (blank counts as 0) and list them in the reportJ–O
6Flag red + bold: displayed value ≥ 0.15% in K–N; raw value > 0.15% in OK–O
7Delete leftover rows with no data from column C onwardC+
8Merge and center each run of the same portA
9Freeze panes at B2 and select B2B2
K
The edge case that mattered

Flag what people see, not what is stored

The team reads the 0.00% format. If a cell shows 0.15% but is not red, it looks like a mistake. So for K–N the skill rounds the way Excel displays it before comparing. Column O is the exception and uses the raw value. Try it:

Σ
What I learned

Working with AI on a real workflow

Start with a real file

Describing rules in the abstract missed things. Running on an actual day's data surfaced the edge cases fast.

The checking is the work

AI did the repetitive part. My value was knowing what "right" looks like and saying exactly why a result was wrong.
